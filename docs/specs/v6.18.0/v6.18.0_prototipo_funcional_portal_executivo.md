## Decisão de UX que organiza todo o protótipo

O pedido original descrevia um "Portal Executivo de Inteligência Logística" com a sensação de uma plataforma de investimentos/banco — não de uma ferramenta operacional. Duas decisões estruturam as 3 telas:

1. **O cliente não deve cair em menus depois do login.** Ele chega direto num Dashboard Executivo com um "Resumo Executivo" em formato semáforo (🟢🟡🔴) e um botão único de destaque — mesma lógica de "próxima melhor ação" usada por apps de investimento, em vez de forçar navegação por dezenas de telas técnicas.
2. **O menu lateral é deliberadamente reduzido** (7 itens) e a maior parte não está implementada nesta versão — os itens não funcionais mostram um aviso claro em vez de navegar para algo que não existe, para nunca dar a impressão de tela quebrada.

## Parte A — Descrição Funcional

### A.1 Navegabilidade

```mermaid
flowchart LR
    A["Login"] -->|credenciais válidas| B["Dashboard Executivo"]
    B -->|botão de destaque\n'Ver oportunidades prioritárias'| C["Oportunidades Prioritárias"]
    C -->|'Voltar ao Dashboard'| B
    B -->|itens de menu não implementados\n(Diagnóstico/Benchmark/Inteligência/\nGovernança/Relatórios/Minha Conta)| D["Aviso: ainda não disponível"]
    D -.->|permanece na mesma tela| B
```

1. **Login** (`v6.18.0_wireframe_portal_executivo_login.html`) — autenticação, sem menu, sem navegação para nenhuma outra tela até credenciais válidas.
2. **Dashboard Executivo** (`v6.18.0_wireframe_portal_executivo_dashboard.html`) — chegada direta pós-login. Nenhum menu intermediário.
3. **Oportunidades Prioritárias** (`v6.18.0_wireframe_portal_executivo_oportunidades.html`) — alcançável só a partir do botão de destaque do Dashboard, com link de volta.

Os 6 itens de menu não implementados (Diagnóstico, Benchmark, Inteligência, Governança, Relatórios, Minha Conta) nunca navegam — mostram um aviso ("ainda não disponível nesta versão") e mantêm o usuário na tela atual.

### A.2 Comportamento e estados

| Estado | Comportamento |
|---|---|
| Login com campos vazios | Validação inline, sem submissão |
| Login com credenciais inválidas | Alerta de erro, foco no campo de senha |
| Login com credenciais válidas | Alerta de sucesso, redireciona ao Dashboard |
| Item de menu não implementado | Aviso curto ("ainda não disponível"), sem navegação |
| Botão "Ver oportunidades prioritárias" | Navega para a Tela 3 |
| Ação "Priorizar" (Tela 3) | Alterna estado local (visual "Priorizada"), atualiza contador "X de 5 priorizadas" — no protótipo é só estado de tela; na implementação real, grava o metadado descrito no PRD §5.3, sem alterar dado do motor analítico |
| "Ver detalhes" de uma oportunidade | Aviso "ainda não disponível" (fora de escopo desta versão, PRD §6) |

### A.3 Apresentação de indicador — Resumo Executivo (semáforo)

Quatro linhas, cada uma com um indicador de status (🟢 bom / 🟡 atenção / 🔴 crítico) e um valor:

- 🟢 Performance Logística: **Boa** (74 pontos)
- 🟡 Benchmark Mercado: **Existem oportunidades** (81% de aderência)
- 🔴 Economia Potencial Identificada: **R$ 842 mil/ano**
- 🟢 Plano de Ação: **7 de 10 ações concluídas**

Regra de cor usada no protótipo (mock — a Especificação Técnica deve confirmar o limiar real, se aplicável, a partir do que `score_logistico.py`/`benchmark.py` já retornam): performance ≥ 70 → verde; aderência ao mercado < 90% → amarelo; economia potencial identificada > 0 → vermelho (é sempre uma oportunidade, nunca "sem cor"); plano de ação ≥ 70% concluído → verde.

### A.4 Apresentação dos 5 KPIs e dos 4 gráficos

KPIs, em cards de leitura rápida: Economia Potencial (R$), Aderência ao Mercado (%), Performance Logística (pontos), Rotas acima do benchmark (contagem), Transportadoras Monitoradas (contagem) — mapeamento à fonte real em `v6.18.0_PRD_portal_executivo.md` §5.2.

Gráficos, todos com dado mock no protótipo (SVG estático, sem dependência de biblioteca externa):
- **Evolução do Frete** — linha, custo real vs. referência de mercado, últimos 6 meses.
- **Benchmark Mercado** — barras comparativas por categoria de custo (empresa vs. mercado).
- **Custo por Região** — barras horizontais por UF (versão simplificada de mapa — ver nota abaixo).
- **Potencial de Economia** — donut, total + composição por categoria de oportunidade.

**Nota sobre "Custo por Região"**: o pedido original sugeria um mapa do Brasil. O protótipo usa barras por UF em vez de um mapa geográfico real, por dois motivos: (1) evita desenhar um contorno de mapa impreciso só para fins decorativos; (2) a Especificação Técnica ainda precisa confirmar a granularidade geográfica real disponível no motor analítico (UF vs. macrorregião, PRD §4) — o protótipo não deve antecipar uma granularidade que o dado real pode não sustentar.

### A.5 Apresentação de recomendação — Plano de Ação e Oportunidades Prioritárias

**Dashboard (Plano de Ação)**: tabela com Ação, Categoria, Status (pendente/em andamento/concluído), consistente com o que `recomendacoes.py` já produz para o analista.

**Oportunidades Prioritárias**: cards ordenados por impacto financeiro anual, cada um com título, descrição curta, categoria, prioridade (alta/média/baixa), status, valor de impacto, e o botão "Priorizar" (único ponto de interação de escrita desta versão, PRD §5.3).
